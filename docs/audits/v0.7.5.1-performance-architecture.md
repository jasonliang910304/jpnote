## Scope and invariants

This checkpoint continues the v0.7.5 performance program without changing learning-data semantics or storage contracts. Priority order remains correctness/data safety, behavior equivalence, architecture cleanup, then speed.

Invariants held for this checkpoint:

- core SQLite schema remains v5;
- Quiz SQLite schema remains v2;
- public import JSON schema remains unchanged;
- fixed-seed Quiz question identity must not drift merely because source reads are batched;
- audit/preflight/export public output must remain equivalent;
- read-only commands must remain side-effect-free;
- import conflict/duplicate behavior remains fail-closed;
- compatibility fallbacks remain where a public/fake reader does not implement the new bulk capability.

## Implemented changes

### 1. Shared study-source snapshot

`StudySourceSnapshot` allows Quiz mixed-mode planning and source-catalog discovery to share one immutable entries+attempts snapshot instead of independently hydrating the same source data. Existing readers that only implement the older methods continue to work through a fallback path.

### 2. Import outcome indexes

`EntryOutcomeSnapshot` and `AttemptOutcomeIndex` provide one-time bulk state for import preflight/safe-fix/apply. Generated-attempt event-key/content identity no longer performs repeated full attempt-table scans. Same-batch identity semantics and legacy raw `aliases_json` normalization behavior are retained.

### 3. Audit/relation bulk indexes

Full audit preloads entry, attempt-link, resolved-relation, pending-relation, and reciprocal/inverse lookup state. The previous reciprocal relation per-pair query path is eliminated. Issue ordering and issue payloads were compared against the exact baseline.

### 4. Read-heavy command cleanup

- romaji audit uses a summary batch read instead of per-entry hydration;
- Markdown export hydrates the full entry set once;
- `list --select` uses bulk full-entry records instead of `get_entry()` per result;
- Quiz source catalog and mixed planning reuse bulk snapshot data where available.

### 5. `parse_payload()` linearization

The legacy parser no longer calls `raw_decode(candidate[position:])` at every `{` candidate. It now performs a whole-document decode first, then a single brace/string-aware outer-object scan when embedded JSON extraction is needed, followed by the existing nested payload discovery and ambiguity checks.

The hard 16 MiB ingest boundary added in v0.7.4 remains in place. Multiple different payloads still fail closed.
