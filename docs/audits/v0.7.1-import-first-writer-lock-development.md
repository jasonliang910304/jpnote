## Scope

1. 序列化 core mutation、backup publication 與 undo restore，修正多程序 snapshot/commit ordering 風險。
2. 讓一般學習改用 `jpnote import FILE`，並只在完整成功後提供來源檔清理。
3. 不修改 core schema v5、Quiz schema v2 或 public import JSON schema。

## Pre-implementation risk rehearsal

- **資料一致性**：若 snapshot 和 transaction 沒有同一鎖，兩個 writer 的 backup 可能與 commit 順序不一致。
- **stale preflight**：互動確認不能長時間持鎖，但確認後另一個 writer 可能改變 DB。正式 apply 前必須在 writer lock 內重算 duplicate warnings／preflight；任何結果 drift 都 fail closed 並要求重跑。
- **undo race**：undo target 選定後若另一個 import commit，restore 可能覆蓋未預期的新資料。
- **crash recovery**：lock file 不可 unlink/recreate；否則 contenders 可能鎖到不同 inode。採 persistent file＋kernel `flock`，process crash 自動釋放。
- **lock-file path attack**：拒絕 symlink、hard link、非 regular file、非目前使用者 owner；使用 fd chmod，取得鎖後再確認 path 仍指向相同 inode。
- **誤刪**：來源檔只有在 DB、backup/export 流程成功後才可處理；check、cancel、failure 不進 cleanup。
- **symlink/path replacement**：final symlink 拒絕；讀取與刪除前記錄並比對 device/inode/size/mtime/ctime，使用 parent `dir_fd`。
- **TOCTOU 殘餘**：POSIX 沒有 conditional unlink-by-inode；同一使用者惡意競速仍存在極小 stat/unlink window。此版本 fail closed 處理一般替換與修改，並在文件中保留限制。
- **非互動卡住**：未明確 `--delete-source` 時，noninteractive／JSON 一律保留。
- **post-commit side effect**：刪檔失敗、cleanup prompt EOF／Ctrl-C 不得拋成 import failure；改為 keep/warning＋structured cleanup status。
- **資源上限**：來源仍由現有 parser 一次載入記憶體；payload size limit 尚未納入本 checkpoint，保留為後續 hardening，不在未定規格下任意加入可能破壞相容性的上限。

## Implemented boundaries

- `mutation_backup()` 持有 writer lock，涵蓋 pre-mutation snapshot、caller transaction/export 與 pending backup publication。
- `command_undo()` 持有同一 lock，涵蓋 backup selection、integrity check、recovery snapshot、restore、move-used 與 export。
- `connect()` 的 migration／orphan pending recovery、manual backup、init、export 也序列化。
- import 在顯示／確認 preflight 後，會於 `execute_safe_mutation()` 所持 writer lock 內重新建立 database-dependent duplicate warnings 並比較完整 preflight；確認後狀態改變時不 apply。
- revalidation 保留 normalized plan 的 internal attempt identity marker，不會把 auto-generated `event_key` 誤當成 explicit key。
- `ImportSource.read()` 單次 UTF-8 讀取，拒絕 final symlink／非 regular file，並偵測讀取期間變更。
- `ImportSource.delete_if_unchanged()` 在刪除前重新驗證 identity 與 metadata。
- CLI flags：`--delete-source`、`--keep-source`；預設互動 `[y/N]`、非互動 keep。

## Residual risks／deferred hardening

- POSIX conditional unlink-by-inode 不存在；同一使用者惡意競速仍有極小 stat→unlink window，已針對一般替換／修改 fail closed。
- import payload size limit 尚未加入，列入後續 hardening。
- writer lock 是本機 filesystem advisory lock；跨主機共享 filesystem 的語意不在本版保證範圍。
- atomic revisioned installer／真正 rollback 仍為下一個高優先項目。
