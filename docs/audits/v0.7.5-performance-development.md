## 2. 已實作

### Quiz hot path

- vocabulary normalized names／reading／meaning／review-group features 每 entry 只建立一次。
- safe-pair 判定具對稱性，因此每個 unordered pair 只計算一次，轉成 per-source exclusion set；不刪除 homophone／alias／meaning-overlap／review-group safety rules。
- 同一 source 的 MCQ／meaning True-False 共用 prepared safe candidates、meaning summary 與 kana-prompt ambiguity result。
- shortage confirmation 直接 persist 第一次建立的 immutable `QuestionPoolPlan`，不再第二次讀 core sources 或重建完整題庫。
- generator version、question identity shape、selection/shuffle semantics 均不變；真正會改 fixed-seed sequence 的 asymptotic redesign 留後續 checkpoint。

### 小型 UX / correctness

- 新增 `jpnote recent --days N`：包含今天在內最近 N 個本機日曆日；`N >= 1`；與 `--date`／`--since` 互斥。
- spaced Hepburn 修正長音後續獨立 mora 被吞掉：例如 `ていいん → tē i n`、`けいえいほうしん → kē ē hō shi n`、`そうおん → sō o n`。
- romaji equivalence 改為 reading-derived canonical 單向判定，避免把少一個 mora 的舊值反向展開後誤判等價。
- 無上下文助詞 `は` 不猜發音；`または ma ta wa ↔ ma ta ha` 繼續 fail-closed review。

## 5. Formal dataset follow-up

actual gate 時正式 DB：1050 items／153 grammar／897 vocabulary／27 attempts。新版 romaji audit 揭露 2 個 safe normalization、1 個舊 converter 真正 mismatch 與 5 個新的片假名 origin review。使用者之後以正式 import/preflight 完成 8 個同-key corrections：

- `定員`：`tei in → tē i n`
- `経営方針`：`kei ei hō shin → kē ē hō shi n`
- `騒音`：`sō n → sō o n`
- `アンケート`、`セーター`、`プラン`、`プレゼン`、`ボウリング`：補 origin metadata

post-correction：

```text
items=1050 / grammar=153 / vocabulary=897 / attempts=27

foreign_key_violations=0

```

11 個 review 中，10 個是已確認刻意保留的同 meaning 不同非空例句；剩餘 `vocab:または` 是 converter 無上下文無法安全判定助詞 `は` 的發音。不要自動把正確學習資料 `ma ta wa` 覆寫成 `ma ta ha`。

## 6. Remaining / not reopened

本 release 不重新開啟 Deep Adversarial Audit。後續 Performance & Architecture Cleanup 仍包括：

- shared immutable source snapshot／bulk hydration/index
- Quiz source catalog/session planning 重複 hydration
- attempt identity one-time index
- import preflight/export/search/list/romaji-audit query-count/scaling
- `parse_payload()` adversarial superlinear scan
- fzf per-keypress subprocess/full normalization
- dynamic Quiz loading indicator
- bounded dead/superseded code cleanup

若未來 asymptotic Quiz redesign 需要改 RNG/shuffle sequence，必須明確建立 generator-version／equivalence boundary，不可在「效能優化」名義下暗改題目分布。

## 7. Tooling UX note

actual Arch gate 顯示 `pytest -q` raw dots 時，各批 progress 長度不同且可能因終端寬度換行。後續 gate script 保留 raw pytest output 到 log，但終端優先顯示固定寬度或分組摘要；這是 release tooling UX，不改產品 runtime。
