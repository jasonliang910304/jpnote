# jpnote v0.6.6.4 Stability-gate 驗證報告

日期：2026-07-24（Asia/Taipei）

> 本報告針對 v0.6.6.3 廣域健檢發現的 Quiz 前 blocker，驗證 v0.6.6.4 集中 maintenance patch。
> 所有破壞性與 migration 測試使用臨時資料庫；使用者提供的真實資料庫只在隔離副本上執行。

## 1. 結論

v0.6.6.4 已修正：

1. relation manual edit 遺失 pending relation／洗掉 provenance。
2. raw SQLite helper connection leak。
3. public core mutation 繞過安全 pipeline。
4. SIGKILL 後 orphan `.pending-*` snapshot 無 recovery policy。
5. corrupt newest backup 卡住 undo、無法指定較舊 backup。
6. auxiliary recovery/restored backup 無 retention cap。
7. second-resolution timestamp 造成 recent 分類風險。
8. explicit selector typo／out-of-range 靜默成功。

完整 regression、coverage、安裝／升級 smoke 與真實 DB 副本 audit 通過。

**Stability gate：PASS。**

下一步開始 Quiz core；非 blocking backlog 不再延後 Quiz。

## 3. Relation logical diff／provenance regression

覆蓋案例：

- A→B resolved 與 A→Missing pending 同時存在。
- 只修改 A→B note。
- 刪除 A→B，但保留 A→C 與 A→Missing。
- reciprocal／inverse 兩端維持一致。

結果：

- pending row 完整保留。
- unrelated resolved rows 完整保留。
- changed relation 更新 note，但既有 `source`／`created_at` 不變。
- 明確刪除只影響指定 logical pair 與 reciprocal/inverse。

**PASS。**

---

## 4. SQLite lifecycle regression

在 Linux `/proc/self/fd` 可用環境中：

1. 建立測試 DB。
2. 暫停 Python GC。
3. 連續執行 100 次 `connect_preflight()`。
4. 比較 open file descriptors。

結果：FD 增量不超過測試容許值 2，未再線性增加。

所有 raw `sqlite3.connect()` helper 改以 `contextlib.closing()` 或顯式 close 管理。

**PASS。**

## 5. Safe Mutation Pipeline regression

`execute_safe_mutation()` 已接入 CLI 與 public API。驗證：

- 真正 modified mutation 才發布 undo backup。
- no-op 不擠掉舊的有效 backup。
- operation exception rollback，pending snapshot 不進 active pool。
- DB commit 後 Markdown export failure 時，資料仍保持 committed，pre-mutation undo snapshot 仍發布。
- public import 在實際 mutation connection 上重建 plan 與 preflight。
- blocking attempt conflict 無法繞過，且不建立無用 backup。
- duplicate warning 必須明確 `accept_warnings=True`。
- public API mutation 會刷新 committed-state Markdown export。

**PASS。**

## 6. Crash／backup／undo regression

### Orphan pending snapshot

- dead PID + valid snapshot：下次 writable connect 提升為 `*-recovered.db`。
- live PID：保持 pending，不誤收。
- corrupt pending：保留供人工檢查，不自動還原。
- legacy 無 PID pending：有 grace period，避免誤收進行中的舊格式 snapshot。

### Undo

- newest backup 損壞：預設跳過，選擇下一個有效 backup。
- `undo --list` 顯示正常／損壞狀態。
- `undo --backup NUMBER_OR_FILENAME` 可指定。
- 明確指定損壞 backup：在建立 recovery snapshot 前拒絕。
- active undo 與 auxiliary recovery/restored 各自執行 50 MiB retention。

**PASS。**

## 11. Deferred backlog

### 不阻塞 Quiz core

1. 多程序 writer 仍可能得到 `database is locked`；Web／GUI／background writer 前加入 busy timeout／retry／serialization。
2. 大量 attempts identity matching 仍可索引化；目前 27 筆 attempts 不構成實際瓶頸。
3. delete impact preview、進階 backup UI 屬產品改善。

### Gate policy

只有下列新發現可以重新阻塞 Quiz：

- 可能錯改／遺失資料。
- preflight／apply 不一致。
- relation invariant 被破壞。
- backup／undo 無法可靠復原。
- 單筆壞資料阻斷 audit／repair／export。
- transaction／migration correctness 問題。

其他 finding 記入 backlog，不再重跑無限期 broad audit。
