## Finding A — Linux installer 不是真正 rollback-safe

v0.7.2 installer 直接刪同版本 `jpnote_app/docs` 再 copy；中斷可能留下半套 app tree。launcher backup 無法還原已刪內容。

### dev1 design

- Python >= 3.10 檢查在任何 install tree mutation 前完成。
- installer 以 `~/.local/lib/jpnote/.install-lock` 的原子 `mkdir` 序列化；既有／stale lock fail closed，不嘗試猜測性刪除。
- `~/.local/lib/jpnote/<version>` 本身維持一般目錄，拒絕 version target／revisions directory 被 symlink 或非目錄替換。
- 新 code 先複製到 `revisions/.stage-*`，驗證 `jpnote_app.config.VERSION` 後 rename 成不再原地覆寫的 versioned revision。
- `current` 是 installer-managed symlink，activation 以同目錄 temp symlink + `os.replace()` 原子切換。
- `jpnote_app`／`docs` compatibility symlink 固定指到 `current/...`；既有非預期 leaf symlink 以 `os.replace()` 安全替換且 failure 時恢復原 symlink，不追蹤／改寫其外部 target；真實目錄則 fail closed。
- launcher 先保存 `cp -P` backup，再以同目錄 temp launcher + `os.replace()` 原子替換；activation state 在 replace 前標記，避免 signal 落在 replace/flag 間造成無法 rollback。post-install `jpnote --version` 失敗時原子恢復舊 launcher 與舊 `current`。
- 成功後不自動刪舊 revisions；先以 rollback 安全優先，避免 installer cleanup 造成新的誤刪風險。

## Finding B — read-only commands 仍會碰實體 DB/filesystem

v0.7.2 的 `connect()` 會 ensure/chmod app dirs、recover `.pending-*`、migrate schema、prune backup、chmod DB。多個純讀取 command 仍使用它。

### dev1 design

新增 `connect_readonly()`：

- DB 不存在：直接建立 current-schema memory view，不建立 data dir／DB。
- current schema：SQLite `mode=ro` 直接開檔，再 `PRAGMA query_only=ON`。
- 舊 schema／缺 table：關閉 direct connection，透過既有 `connect_preflight()` 複製到 memory 並只在 memory migration。
- future schema：fail closed。
- 純讀 command 改用此 path；`init`、manual export、undo/mutation 保持 writable path。
- backup listing 另加 side-effect-free listing helper；實際 backup/prune/undo 邏輯仍使用原本 secure helper。

## Finding C — explicit Quiz DB path 會 chmod 外部 parent

`QuizSessionStore` v0.7.2 無條件 `_secure_directory(self.path.parent)`。若 `path=` 或 `JPNOTE_QUIZ_DB` 指向既有共享目錄，會把 parent 改 0700。

### dev1 design

- constructor `path=` 或 `JPNOTE_QUIZ_DB`：只 `mkdir(..., exist_ok=True)`，不 chmod 既有 parent。
- default／`JPNOTE_DATA_DIR` app-owned parent：維持 0700。
- quiz.db 本身維持 0600。

## Finding D/E — core CI 與最低 Python 未明確

v0.7.2 只有 Windows client workflow 的 targeted protocol/client tests；一般 core/Quiz 修改不會自動跑完整 regression。文件只寫 Python 3，但程式已依賴 Python 3.10 語法／功能。

## Dev2 recent UX implementation

精確 baseline：使用 actual dev1 gate 後建立的 `jpnote-v0.7.3-dev1-worktree-20260809T030125.tar.gz`，SHA-256 `43d325f28b5f0e4cf2a361159c6aa342a316d55e1ca2efed9476b53d65fb9cac`；不再從 GitHub release commit 猜未提交 dev1 working tree。

### Import preflight update details

- core `build_preflight_report()` 新增 `updates[]`；每筆包含 type/display/stable key 與 `changes[]`。
- changes 依正式 upsert merge semantics 描述 scalar replacement、aliases merge/cleanup、meaning/example additions/removals、source additions、related_grammar new/update；不把空 optional field誤報成覆寫。
- `render_preflight_text()` 直接呈現；一般 `jpnote import` 的內建完整 check 因共用同 report 自動同步。
- `jpnote.import.v1` 保持 protocol v1，新增欄位為 backward-compatible extension；preflight token 自然綁定新 report。
- Windows 0.7.3 client 只呈現 `preflight.updates[].changes[].text`，不自行推算 diff；`Test-JpnoteFile` 與 `Import-JpnoteFile` 共用。

### Grammar romaji search

- search normalization 只從 grammar key/display/reading/aliases 抽取 contiguous kana runs，再用既有 Hepburn converter 產生 search-only variants。
- `V/N/A/～/＋/／` 等 notation 不需要存進 romaji 欄位；例如 `imasu` → `いる／います`、`teiru` → `Vている`。
- 漢字沒有 kana reading/alias 時不猜讀音；不修改 canonical/display/public schema。

### Quiz direct count input

- setup focus 在題數列時，數字鍵進入 count buffer；Enter commit、Backspace/Delete 修正、Esc 取消 buffer。
- 合法範圍維持既有 1–100；0 fail closed，超過 100 的追加 digit 被拒絕並顯示提示。
- ←/→ 仍可逐題調整；題庫不足仍使用既有 shortage report/confirmation，不改 session schema。

### Development hygiene rule

後續每次成功 dev gate／release 都固定清理 obsolete patch、validation scripts、SHA sidecars、過期 worktree snapshot、stale temp dirs 與已被成功結果取代的 failed logs；保留最新成功 validation log、正式 DB safety backup、rollback/release artifacts。失敗時先保留診斷資料，直到後續 gate 成功再清。

Dev2 完成開發端 regression 後才交 actual Arch gate；Windows client 0.7.3 real gate 延後與 v0.7.3 release 前最後一次整合驗證合併，避免重複往返。
